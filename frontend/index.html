      How monitoring works

      After every payment, the buyer agent runs 4 automated quality checks on the response. This produces data that on-chain records alone can't provide.

      Response check

      Did the seller actually respond with data? A payment with no delivery gets flagged immediately.

      Format validation

      Does the response contain the expected fields for the task type? Missing fields = broken service.

      Data plausibility

      Are values in sane ranges? A price oracle returning $0 or a validator count of -1 gets caught.

      Freshness check

      Was the data generated recently? Stale responses from cached or dead services are flagged.

      Latency tracking

      Response time measured per request. Tracked but not scored against the seller — network delays aren't their fault.

      Cross-protocol view

      Attestations aggregate across protocols. If a seller degrades on one, buyers on another know about it.

      Why this matters. On-chain data tells you payments happened. It can't tell you if the data was fresh, the format was valid, or the service was actually working. That's what buyer attestations provide — the quality signal that no amount of Solscan scraping gives you.
